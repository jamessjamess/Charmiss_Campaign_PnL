## 3. ข้อมูล

### 3.1 Target แยก SKU × Channel — สัญญาข้อมูล (target contract)

ปัจจุบัน Target ระดับ SKU มาจาก Sheet (ไฟล์ P&L) · ต่อไปจะมาจาก **ระบบตั้ง Sales Target** อีกตัว (Total → Channel → Sub-channel → SKU → Month) → ให้แยกจุดรับข้อมูลไว้ตั้งแต่ตอนนี้
- เขียน `docs/TARGET_CONTRACT.md`: CSV 1 แถว = SKU × Sub-channel × เดือน · คอลัมน์ `campaign · sku_code · sku_name · channel (MT|TT|ECOM) · sub_channel · month (yyyy-mm) · target_qty · target_net_sales (ex VAT) · source · updated_at`
- ETL: ถ้ามี `data/targets/<campaign>.csv` → ใช้แทน Target ใน P&L sheet ของ Campaign นั้น · ไม่มี → ใช้ P&L sheet เหมือนเดิม · seed เก็บ `target_source` ต่อ Campaign · SEED_REPORT และบรรทัด Source บอกว่า Target มาจากไหน
- **ห้ามแก้ Target ในเว็บ** (เว็บอ่านอย่างเดียว)

### 3.2 Mock sales actual (สำหรับรีวิว design — ยังไม่มี Sales actual จริง)

- `src/mock.js` (pure · คำนวณตอนเปิดเว็บ ไม่เขียนลง seed) → `CP.mock.salesActual(seed, today)` คืนแถว sales `scenario:'actual'` พร้อม `mock:true`
- ทำเฉพาะ Campaign ที่มี Target · เดือนตั้งแต่เดือนที่เริ่ม Campaign จนถึงเดือนก่อนเดือนปัจจุบัน + เดือนปัจจุบันแบบ MTD (× วันที่ ÷ จำนวนวันของเดือน)
- ค่าแบบสุ่มที่ **ได้ผลเดิมทุกครั้ง** (PRNG ตั้ง seed ด้วย hash ของ `campaign|sku|sub_channel`): factor ต่อ SKU × Sub-channel — ราว 25% Behind (0.55–0.85) · 25% At risk (0.90–0.99) · 50% On target (1.00–1.25) · noise รายเดือน ±10% · qty = round(target_qty × factor) · amount = target_amount × factor
- **ไม่ mock ค่าใช้จ่าย** — Spend ใช้ของจริงเสมอ
- สวิตช์ **Data: Real | Mock** ใน top bar ต่อจากป้าย DEV · default **Real** · จำค่าต่อคน
- เมื่อเปิด Mock: ปุ่ม Mock สี warn · แถบเตือนใต้ page banner (พื้น `--warn-soft`) *"Mock sales actuals — generated from targets for design review. Not real numbers."* · legend เขียน `Actual (mock)` · ไฟล์ Export ต่อท้ายชื่อด้วย `_MOCK` และ sheet แรกมีบรรทัดเตือน
- โหมด Real ต้องได้ตัวเลขเท่าเดิมทุกตัว (anchor §0)

### 3.3 จับคู่ชื่อรายการค่าใช้จ่าย

- `data/expense_lines.csv`: `raw_name · line · group (Marketing|Sales)` · ETL ใช้ชื่อ `line` · ชื่อที่ไม่มีในตาราง → ใช้ชื่อเดิมและเตือนใน SEED_REPORT

## 4. นิยามตัวเลขใหม่ (เพิ่มใน `src/rules-pnl.js` · ฟังก์ชันเดียวต่อเรื่อง)

| ตัวเลข | สูตร |
|---|---|
| Months with actual | เดือนที่ Campaign มี Sales actual อย่างน้อย 1 แถว · **ภายในเดือนเหล่านี้ ช่อง SKU × Channel ที่ไม่มี actual = ขาย 0** (ไม่ใช่ข้อมูลหาย) · นอกเดือนเหล่านี้ = `null` |
| Target to date · Actual to date | Σ ของ months with actual · กรองตาม Channel / Sub-channel / SKU |
| Ach % | Actual to date ÷ Target to date (D3 เดิม) |
| Gap | Actual to date − Target to date (ติดลบ = ตามหลัง) |
| Status | **On target** ≥ 100% · **At risk** 90–99.9% · **Behind** < 90% · มี target แต่ยังไม่มีเดือนที่มี actual = "—" · มี actual แต่ไม่มี target = **No target** |
| Time | Elapsed % = (วันนี้ − Start + 1) ÷ (End − Start + 1) · Days left = End − วันนี้ · ใช้ End campaign (End marketing แสดงประกอบ) |
| Remaining target · Required run-rate | Full target − Actual to date · Remaining ÷ จำนวนเดือนที่เหลือหลังเดือนล่าสุดที่มี actual จนถึงเดือน End |
| Current pace | ค่าเฉลี่ย Actual ต่อเดือน ของ months with actual ที่ครบเดือน (ไม่นับเดือน MTD) |
| Forecast (**Est.**) | Actual to date + Current pace × เดือนที่เหลือ · ติด badge **Est.** ทุกที่ที่โผล่ |
| Waterfall steps | Net revenue (+) → COGS (−) → **Gross profit** (subtotal) → Marketing exp (−, กางเป็นรายการได้) → Sales exp (−, กางได้) → **Campaign profit** (total) · ใช้ `R.statement()` ชุดเดียวกับตาราง statement |

ทุกค่าในแท็บใหม่ต้องเท่ากับค่าเดียวกันในแท็บอื่นเมื่อ scope ตรงกัน (เช่น Campaign profit ของ Waterfall เมื่อเลือก 1 Campaign = แถว Profit ของ Campaign นั้นใน Portfolio)
