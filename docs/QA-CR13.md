- **ทั้งวงจรใช้งานได้จริงตั้งแต่ต้นจนจบ**: สร้างแคมเปญ → 7 ขั้น (5 คน) → ส่ง → Executive ขอแก้ → แก้ → ส่งใหม่ → อนุมัติ → ขอปรับช่วงเวลา + ปรับงบ → อนุมัติ → ปิดแคมเปญ → Admin เปิดใหม่ → History ครบ

  - ภาษา / ธีม / Export / Ctrl+K / Product Master ทำงาน
- **พบ 25 จุด**:
  - **สูง 3** — ตัวเลขที่ Executive ใช้ตัดสินผิด · ตัวช่วยตั้งเป้าใช้ค่าเริ่มต้นไม่ได้ · ปุ่ม Undo กดไม่ได้
  - **กลาง 8**
  - **ต่ำ 14**
- **Journey โดยรวมลื่น** แต่มี 4 จุดที่ทำให้งานสะดุดหรือเข้าใจผิด:
  1. คนที่ถูกส่งกลับไม่เห็นเหตุผลในหน้าที่ระบบพาไป
  2. ขั้นตอนเดินเรียงต่อกันยาว 7 ขั้น (ใช้เวลา 45 วันตาม Due)
  3. เลื่อนช่วงเวลาแล้วเป้าไปกองในเดือนเดียว

| B24 | ประวัติ: กดเสร็จ 1 ครั้งเกิด 2 แถว (บันทึกฉบับร่าง + ทำขั้นเสร็จ) → 20 แถวสำหรับแผนเดียว | รวมเป็นแถวเดียว หรือซ่อน "บันทึกฉบับร่าง" ที่เกิดพร้อมกันไว้ใต้ตัวกรอง "การแก้ไข" |
| B25 | มือถือ: หน้า Planning การ์ด KPI 4 ใบเรียงก่อนรายการ (ต้องเลื่อน 3 จอ) · ตารางเป้าแก้บนมือถือ ช่องที่เลือกทับชื่อ SKU | KPI เป็นแถบเลื่อนแนวนอน · ตารางบนมือถืออ่านอย่างเดียว + `แก้บนคอมพิวเตอร์` |

## 4. Journey ตามบทบาท

| บทบาท | ราบรื่น | สะดุด |
|---|---|---|
| **ผู้ทดสอบครั้งแรก** | ไทยเป็นค่าเริ่ม · Dashboard โหลดเร็ว | เปิดมาเป็น **Ann (ผู้บริหาร)** — สร้างแคมเปญไม่ได้โดยไม่รู้ว่าทำไม · ไม่รู้ว่าต้องสลับ "ใช้งานในนาม" |
| **Brand (owner)** | สร้าง → ขั้น 1, 2 เร็ว · วงเงินงบเข้าใจง่าย · หน้าแคมเปญหลังอนุมัติครบในหน้าเดียว | ต้องรอ Sales ทำเป้าก่อนจึงตั้งวงเงินได้ · ถูกส่งกลับแล้วไม่เห็นเหตุผล (B4) · กดเสร็จแล้วต้องหาขั้นถัดไปเอง (B22) · เพิ่ม SKU ทีละตัว |
| **Sales** | ตัวช่วยตั้งเป้าลดงานจากการพิมพ์ 60 ช่องเหลือ 5 ช่อง | ใช้ครั้งแรกติด 99.9% (B2) · ไม่มีปุ่มคัดลอกจาก "แคมเปญหมวดเดียวกัน" ให้เลือกง่าย (รายการคัดลอกยาวทุกแคมเปญ) |
| **Marketing / Finance (แตกรายการ)** | วงเงิน / แตกแล้ว / คงเหลือ ชัด · "เกลี่ยส่วนที่เหลือ" ประหยัดเวลา | ต้องกดบันทึกเองถ้าออกก่อนกดเสร็จ (เบราว์เซอร์เตือนแล้ว) · รู้ว่าถึงคิวตัวเองจาก My tasks เท่านั้น |
| **Executive** | คิวพิจารณาเลื่อนต่อเองได้ · มี "อะไรเปลี่ยนไป" · ห้ามอนุมัติของตัวเองทำงาน | ตัวเลขคำขอปรับงบผิด (B1) · Undo กดไม่ได้ (B3) · ต้องเลื่อนจนสุดก่อนอนุมัติ (ดีด้านการควบคุม แต่ยาว) |
| **Admin** | เปิดใหม่ / แก้รายชื่อได้ | สร้างแคมเปญแทน Brand แล้วกลายเป็น owner เอง (B19) |

## 5. ข้อเสนอปรับ Process

| # | ปัญหาที่เห็น | ข้อเสนอ | ผล |
|---|---|---|---|
| **P1** | 7 ขั้นเดินเรียงกัน Due ห่าง 75 → 30 วันก่อน Start · วงเงินต้องรอเป้าเสร็จ · 3 ฝ่ายรอวงเงิน | **Brief ก่อน (ขั้น 1):** owner ใส่เป้าทั้งหมด + วงเงิน % ตั้งแต่ขั้น 1 → **ขั้น 3 (Sales แตกเป้า) กับขั้น 5 (3 ฝ่ายแตกงบ) ทำพร้อมกันได้** · ขั้น 4 กลายเป็น "ตรวจวงเงินกับเป้าจริง" | รอบวางแผนสั้นลงจาก 7 ช่วงเหลือ ~4 ช่วง · ตรงกับวิธีที่ทีมคิดจริง (Top-down ก่อน แล้ว Bottom-up) |
| **P2** | ส่งกลับแล้วทุกคนต้องเข้าไปหาเองว่าต้องแก้อะไร | ส่งกลับ = งานใน My tasks ของคนที่ถูกติ๊ก **พร้อมความเห็น** + แถบเหตุผลในหน้า (B4) | แก้รอบเดียวจบ |
| **P3** | ปรับช่วงเวลาแบบเลื่อนทั้งแคมเปญ (ช้าไป 1 เดือน) → เป้า ก.พ. ฿2M ไปกองที่ มี.ค. · เดือน ก.ค. ที่เพิ่มมาว่าง | เพิ่มตัวเลือก **"เลื่อนทั้งแผน n เดือน"** (ย้ายเป้า / งบทุกเดือนตามไป) คู่กับแบบเดิม "คงเดือน · ย้ายส่วนที่หลุด" | เป้ารายเดือนยังสมจริง · Pace ไม่เพี้ยน |
| **P4** | หลังอนุมัติแก้ได้แค่งบ / ช่วงเวลา · ถ้าตลาดเปลี่ยนต้องการ **ปรับเป้า** ทำไม่ได้ | "Revise plan" = แผนฉบับใหม่ (v3) ผ่านการอนุมัติแบบเดิม (นอกขอบเขต CR-13 — ควรเป็นงานถัดไป) | ตัวเลขเป้าใน Dashboard ตรงกับความจริง |
| **P5** | ทดสอบหลายคนพร้อมกันไม่ได้ — แต่ละคนเห็นข้อมูลในเบราว์เซอร์ตัวเอง (ไม่มี DB) · Ploy ส่งจากเครื่องตัวเอง Ann เปิดอีกเครื่องจะไม่เห็น | ระยะสั้น: แถบบอกบนเว็บ `เดโม — ทุกบทบาทอยู่ในเบราว์เซอร์นี้ · สลับคนที่ "ใช้งานในนาม"` + ปุ่ม **ส่งออก / นำเข้าข้อมูลเดโม (.json)** ให้ส่งต่อกันได้ · ระยะถัดไป: ต่อที่เก็บกลาง (Google Sheets + Apps Script หรือ Supabase) สำหรับ UAT | ทดสอบ UAT กับทีมจริงได้ |
| **P6** | เปิดครั้งแรกเป็น Executive | หน้าต้อนรับครั้งแรก "คุณคือใคร" (เลือกบทบาท) หรือค่าเริ่ม = Ploy | คนใหม่เริ่มงานได้ทันที |
| **P7** | การแจ้งเตือนมีแค่ badge ในเว็บ | ปุ่ม "คัดลอกข้อความแจ้ง" (ลิงก์ + สิ่งที่ต้องทำ) ไปวางใน LINE / Teams · ต่อ DB แล้วค่อยทำแจ้งเตือนจริง | ไม่ต้องรอให้คนเข้ามาเช็กเอง |
| **P8** | ปิดแคมเปญ: Executive เป็นคนเดียวที่ยืนยัน แต่ข้อมูลค่าใช้จ่ายค้างอยู่ที่บัญชี | ในฟอร์มปิด เพิ่มช่อง "ฝ่ายการเงินยืนยันไม่มีค่าใช้จ่ายค้าง" (ติ๊กโดย Mai) ก่อนส่ง Executive — ไม่เพิ่มขั้นอนุมัติ | ปิดแล้วไม่ต้องเปิดใหม่บ่อย |
